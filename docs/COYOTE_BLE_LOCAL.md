# 郊狼 + 负鼠 BLE 直连（v1.2.0 实验性适配）

支持一台郊狼 2.0 或 3.0，与一台负鼠同时由电脑蓝牙直连；也可以只连接其中一台。连接方式整体选择：V3 Socket、V4 Socket、或全蓝牙。蓝牙模式不启动 Socket 服务，也不能把其中一台留在 App / Socket 模式。

## 使用
设备与游戏 → 蓝牙直连 · 郊狼 + 负鼠 → 检测并连接设备 → 找到唯一设备后自动连接 → 等待确认归零 → 各自手动启用。
郊狼请拨动模式按钮，切换到蓝色蓝牙模式。检测窗口约 5 秒，进度条按实际耗时推进；进入连接与归零确认阶段后使用不定进度和旋转 SVG 沙漏，不把时间百分比当作连接确认。
同类设备有多台时需手动选择，不随机连接。检测和连接均可取消；取消或切换模式后的旧扫描结果不能再次发起连接。
先在手机 App 中断开相应设备。电脑需支持 BLE。若搜不到负鼠，连续按五次开机键，蓝牙图标变黄后重新扫描。
两类设备的列表分别过滤，不能把负鼠选成郊狼。共用一次显式扫描，已连接、停止广播的设备在重扫后仍保留。仅点击检测后的本轮结果会触发一次自动连接。没有后台自动扫描、断线自动重连或自动启用输出。设备地址不保存到配置。

## 保留的策略
- 郊狼继续使用现有心率 / 动作、A/B 独立来源、预设 / 自定义波形、随机 / 队列等策略。
- 负鼠继续使用原有工作台：同步游戏振动器实际档位，或 A/B 独立配置动作、自定义曲线、固定和随机轮播。游戏随机档位以遥测传入的实际低 / 中 / 高为准。
- 各自保留硬上限。郊狼软件强度范围仍为 0–100；负鼠为 0–200，不混用两者的量程。两台设备在独立的工作线程 / 事件循环发送，UI 切页不负责持续发送。
- 全局停止、模式切换、退出都停止两台；单台断线只撤销该台的授权。恢复需重新连接并手动启用。游戏数据过期先归零待机，只有用户仍保持启用且收到新的有效游戏数据时才继续。

## 原生协议
### 郊狼 3.0
180C / 150A / 150B。B0 每个窗口携带 A/B 的四组 25ms 数据。强度变化使用非零序列号并等待匹配 B1；相同强度的后续帧不重复请求强度变化。首次连接及重新连接先写 BF 软上限 0，再确认 B1 的 A/B 为 0。
启用后按用户当前硬上限写 BF，平衡参数显式设为 0（并非官方 App 默认值）。BF 会保存到硬件，之后回到手机 App 使用时需重新检查其软上限和平衡设置。软件不自动将强度放大到硬件的 200。

### 郊狼 2.0
955A UUID，1504 为两通道强度；按官方表，1506 对应 A 波形、1505 对应 B 波形。强度使用三字节小端，软件显示值 ×7，读取确认；每通道单独写 X/Y/Z。Z 不超过 20。
原生每个窗口为 100ms；将现有四个采样的周期和宽度作平均并向下取整到 Z，损失部分 25ms 细节，不承诺与 3.0 体感一致。2.0 没有 BF 硬件软上限，不伪造该功能。

### 负鼠
蓝牙名称 47L127000，180C / 150A / 150B。
- B0：20 字节，一次携带 A/B 各四个振幅样本（0–100），对应 100ms。
- B3：A/B 强度（0–200）。归零和强度变化需等待匹配的 B3 状态回报，超时禁止启用 / 停止输出。
- B2：收到 B3 后同步设备屏幕强度，使用官方文档的固定字节串和当前回报值。该报文超过 20 字节，使用带应答 GATT 写入，不自行拆包；固件或蓝牙栈拒绝时停止并显示错误。
- 协议没有序列号、App 通道上限、配件插入状态或电路状态报告，不伪造这些反馈。请自行确认配件插好。B3 只在状态变化时上报的固件，若归零后没有回报，当前保守实现会阻止启用，需要实体测试确认。
- D0 按键事件不作为强度确认。物理按键将强度调到软件上限以上，或在未授权时产生非零强度，会停止输出。
- 连接后仍保持零输出，不能把 GATT 写入完成当成非零输出授权。

## 验证边界
使用假 GATT / BLE 扫描器和 localhost 模拟 App；未扫描或连接实体设备。
两代郊狼与负鼠的实体输出、2.0 实际 A/B 接口对应、负鼠固件 B3 回报和 B2 长写行为、适配器多连接稳定性与体感均待实测。没有承诺更多同类主机的多连上限。硬件验证边界不因发布而改变。
