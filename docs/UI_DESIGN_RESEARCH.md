# 整体与细节 UI 协调调研（2026-10-25）

> 后续调整：已移除外观弹窗与单独的动画选项，顶部按钮直接切换日间／夜间主题。以下保留此前阶段的设计与验证记录。

本调研形成的方案已于 2026-10-26 落地：公共主题与控件、所有侧栏页面的配色迁移、本地 SVG 导航、键盘操作、NPC 响应式排版及减少动态效果。验收与性能测量见 [UI_COHESION_VALIDATION.md](UI_COHESION_VALIDATION.md)。以下保留调研时的观察和设计依据，作为实施前后的对照。

## 现状与优先处理点

依据：当前 QML 源码、1120×720 中英文截图、深浅主题、150% 缩放，以及 NPC 开关的状态复现。

| 观察 | 对使用体验的影响 | 下一步建议 |
| --- | --- | --- |
| `ControlCenter.qml` 有 AppButton/AppTextField；强度页、玩法页、波形页又各自定义 ActionButton、Caption、Choice 等，色板也重复三份 | 同类控件的边框、禁用、焦点、间距容易逐渐不同 | 提取一个主题对象和公共控件目录，先保持布局，只替换样式定义 |
| 页面标题与内容卡片标题有重复；卡片、输入框、列表项普遍都有金色框 | 信息层级不够清晰，主操作不突出 | 页面只留一个主标题；结构卡片使用留白和低对比背景，金色集中在主操作、选中和焦点 |
| 主页面和独立编辑器的按钮、字号、圆角、间距分别维护 | 全局看起来接近，但细节不像同一套组件 | 建立明确的尺寸、字号、间距与语义颜色表 |
| 侧栏使用多种 Unicode 符号，部分字体和符号视觉重量不同 | 导航图标对齐，但字形大小与粗细不一致 | 换成同一套本地 SVG 图标，统一 20 px 画布与笔画；不依赖网络图标字体 |
| 玩法设置有保存草稿；波形库操作立即保存；NPC 配置还需重启游戏生效 | 用户可能把“已保存”理解成“已经在游戏中生效” | 统一状态用语：未保存、已保存、待重启生效。保留各功能真实行为，不假装全部即时生效 |
| 原有仪表盘／监视页仍有 SectionTitle 重复布局警告 | 说明布局存在重复求值；尚不能据此推断全部卡顿原因 | 在大范围美化前用 QML Profiler 定位，再简化有问题的布局依赖 |
| 英文窄窗口的 NPC 字幕／语音设置整行过宽，截图中右侧小开关被裁切；本轮修复的大开关正常 | 单纯扫描文本的布局检查会漏掉整行容器越界 | 下一步将字幕语言与音频开关分组换行，并把容器相对可视区域的边界加入检查；此项作为整体 UI 调整待办 |

Qt 官方推荐优先使用现成 Controls，再通过自定义样式满足需求；可复用控件适合独立成 QML 文件。现有项目已经使用 Basic，自定义外观可继续建立在它上面。[Qt 最佳实践](https://doc.qt.io/qt-6/qtquick-bestpractices.html)、[控件自定义](https://doc.qt.io/qt-6/qtquickcontrols-customize.html)

## 建议的统一规格

以下数值是针对本项目桌面密度的设计提案，并非照搬某个系统的强制标准。

| 项目 | 建议 |
| --- | --- |
| 间距 | 4 / 8 / 12 / 16 / 24 / 32；页边距 24，卡片内边距 16 或 24，字段间距 12 |
| 字号 | 页面标题 24；分组标题 18；正文和控件 14；说明 12；数值可用 16–20 |
| 字体 | 中文使用 Microsoft YaHei UI，英文使用 Segoe UI；表单正文常规字重，主标题与主操作半粗；避免同时混用装饰字体 |
| 控件 | 默认高度 40；密集工具按钮 32；重要的大开关可保留 56–58。尺寸变化应由语义决定 |
| 圆角 | 输入与按钮 6，卡片与弹窗 10；同层级一致 |
| 按钮 | 每个区域最多一个主操作；其余使用次级或文本按钮；删除使用危险色并保留现有确认逻辑 |
| 表单 | 标签在控件上方、左对齐；错误在相应字段附近；说明段落自动换行；窄窗口减少列数 |
| 动效 | 只对状态切换使用短过渡；持续动画仅限当前可见的预览／监视；后续提供减少动态效果选项 |

Windows 的表单指南强调标签、分组、间距及响应式布局，字体指南强调用字号与字重建立信息层级。这里采用其原则，具体尺寸依据本项目的密集桌面设置页调整。[表单布局](https://learn.microsoft.com/en-us/windows/apps/develop/ui/controls/forms)、[Windows 字体层级](https://learn.microsoft.com/en-us/windows/apps/design/signature-experiences/typography)

## 颜色与可读性

当前暖色说明文字并非普遍难读：源码色值计算的对比度，深色说明文字为 8.159:1，浅色为 5.279:1。但输入边框相对于输入背景约为 1.809:1／1.716:1，需要检查这些边界是否承担必需的识别作用。不要把装饰卡片边框与交互边界合用一个颜色。

建议拆分 `surface`、`surfaceRaised`、`textPrimary`、`textSecondary`、`borderDecorative`、`borderControl`、`accent`、`focus`、`danger`；禁用状态另设语义颜色，避免只靠统一降低整个控件透明度。

供下一步试样的暖中性色板：

| 角色 | 深色 | 浅色 |
| --- | --- | --- |
| 背景 | #11100E | #F6F4EF |
| 内容表面 | #191713 | #FFFEFB |
| 输入表面 | #23211D | #F0EDE6 |
| 主要文字 | #F4F1E9 | #25231F |
| 次要文字 | #B9B3A6 | #6F695E |
| 交互边界 | #777064 | #837A6C |
| 品牌金色 | #E7C36B | #916710 |

已计算上述正文配色为 15.857:1／15.552:1，次要文字为 8.575:1／5.397:1，交互边界对输入背景为 3.280:1／3.617:1。结果见 `build/ui-polish-palette.json`；这只覆盖列出的颜色对，不是整个产品的合规认证，其他状态和透明度仍需实测。

可把 WCAG 的普通文本 4.5:1、关键非文本识别信息 3:1 作为设计验收参考；不可用控件有例外，装饰边框无需一概加深。[文本对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)、[非文本对比度](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)

## 开关与动画的细节原则

NPC 大开关这次已经明确绑定 `npcMasterSwitch.active`，并把文字和滑块分区，避免误取窗口的 `active`。下一阶段可把它抽成具有键盘焦点、Space 操作和可访问名称的公共 Switch 控件。

开关应表达二元状态；需要显式保存的表单仍使用勾选框配合保存按钮。NPC 的选项虽即时写入配置，但游戏效果需要重启，应持续显示“待重启生效”，不把配置状态等同于游戏运行状态。[Windows 开关指南](https://learn.microsoft.com/en-us/windows/apps/develop/ui/controls/toggles)

用户已选择“只用自适应预览”：短波形显示 3 个周期，整屏 5 秒滚完；长波形显示 5 秒真实窗口。画面标注慢放倍率，横轴保持真实时间单位；无起点圆点、无模式选择器。0.1 秒波形实际显示 0.3 秒数据，约慢放 16.7 倍；文件和设备播放不变。

后续美化不宜增加大面积无意义动画。性能优化要先测量，持续图表与隐藏页面分开处理；减少动态效果也应纳入状态设计。[Qt 性能建议](https://doc.qt.io/qt-6/qtquick-performance.html)、[W3C 动画说明](https://www.w3.org/WAI/WCAG21/Understanding/animation-from-interactions)

## 分阶段实施建议

1. **统一底层组件**：建立主题对象与 Button、TextField、ComboBox、NumberField、CheckBox、Switch、Dialog、ScrollBar；保留现有数据保存与设备逻辑。先做正常、悬停、按下、焦点、禁用、错误的组件状态页。
2. **逐页整理层级**：先改玩法设置、个性化范围、波形工作台和 NPC 语音；合并重复标题、统一工具栏与保存反馈。其余页面随后迁移，避免一次改变所有操作位置。
3. **验收与性能**：中英文、深浅色、100%/125%/150%/200% 缩放，1120×720 与 1320×840；检查文本换行、Tab 顺序、焦点、弹窗、未安装与加载／错误状态。另用 Profiler 检查重复布局、可见预览的帧耗时和隐藏页面更新。

完成标准应包括：同类控件外观和交互一致；无文字／滑块遮挡；标签和保存语义明确；无新布局警告；已校准强度、草稿、配置键、波形数据及实际播放节奏均保留。
