# 波形工作台与玩法设置开发版（2026-10-25）

本轮在修改前建立源码快照，保留 V3 Socket，不迁移 V4，不提交或推送。

## 配置入口

- **个性化范围**：日常最低/最高、A/B 各自硬上限、强度同步方向、升降速度、强度合成方式、来源权重、弱/中/强比例，以及高潮/失败的强度百分比。
- **玩法设置**：本次启动首次进入时先二选一并确认：原版心率／动作、A/B 独立绑定。确认进入编辑，点击「保存玩法设置」才应用。之后从其他侧栏页返回会保留当前编辑位置；点击「重新选择」可切换，两种玩法的草稿均保留。
- **玩法设置 → A/B 独立 → 检测绑定**：设置通道开关、绑定设备（振动器/活塞机/不绑定）、强度来源、输入阈值和映射曲线。新用户默认 A 振动器、B 活塞；模板只修改草稿，保留已校准强度和硬上限。新增来源使用默认比例。
- **玩法设置 → A/B 独立 → A/B 通道规则**：各自设置默认波形和条件规则。高潮固定最高优先级，其次是失败事件，最后是普通规则；同级按列表顺序。动作使用可搜索的中文多选，未选择表示所有动作；底层稳定键继续保存。档位菜单显示弱/中/强。
- **玩法设置 → 原版心率／动作**：开始／满幅心率与原始动作渐升、高潮双击、失败触发及原有波形选择逻辑；固定/智能模式、分段和动作波形单独保存，不受新版规则覆盖。
- **波形工作台**：导入、动态预览、收藏、分类、复制、改名、完整帧编辑、删除和导出。内置波形先复制再编辑。波形库操作立即保存。

预览采用自适应窗口：短波形只显示 3 个周期，整屏用 5 秒滚完；长波形显示 5 秒真实窗口并按实际速度滚动。界面标注慢放倍率，横轴保持真实时间单位；不提供额外模式选择器。无起点圆点。切换波形、收藏或编辑后立即更新，每帧只绘制可见采样，隐藏页面时停止计时。慢放不改变文件或设备播放。

个性化范围与玩法设置各自持有草稿，按字段归属保存。波形编辑器也会在关闭窗口时检查未保存内容。保存另一页面后，过期草稿会要求重新载入，避免把来源或强度悄悄写回旧值。配置写入失败不改变运行中的设置；已有规则引用的波形不能删除，包括禁用规则的引用。

## 建议的基础玩法

两种模板都以 A 振动器、B 活塞机开始，可交换绑定，也可让两通道绑定同一设备：

1. **档位控制强度**：日常最高 × 弱/中/强比例，波形由玩法设置的规则单独选择。
2. **遥测控制强度**：默认心率，可改为动作发生、动作进度、兴奋度或 NPC 警觉度。动作发生不依赖兴奋度；动作进度保留原有进度含义。绑定设备关闭或数据不可用时，普通输出停止；高潮可抢占。不绑定设备时可做通用映射。

模板会重建普通规则并保留高潮/失败设置，仅修改草稿；已有强度范围和硬上限保留。模板和新用户采用用户截图选定的完整波形：

| 用途 | 参考项目原名称 | 完整帧数 / 时长 |
| --- | --- | --- |
| 振动器 | 官方示例 - 呼吸 | 12 / 1.2 秒 |
| 活塞机 | 默认 - 活塞机 | 4 / 0.4 秒 |
| 高潮 | 默认 - 高潮 | 4 / 0.4 秒 |

高潮规则可以禁用或选择其他波形，但启用时始终最高优先级，包括与失败同时触发的情况。事件立即抢占，不等待普通防抖、保持或周期结束；窗口结束后根据当前状态恢复。事件强度按日常最高值的百分比计算，仍受通道硬上限、设备反馈上限和峰值限制约束。

A/B 上限分离，通道强度和日常范围支持 0–200；波形内部振幅与档位百分比仍为 0–100。取消可调的全局上限。旧 schema 2 的每通道有效上限先取 min(旧全局,旧通道)，迁移后分别修改；schema 3 升级到 schema 4 时保留原有 A/B 上限，不自动提高。同步可选关闭、A→B、B→A，仅复制目标强度；接收通道仍受自己的上限、设备激活状态及波形开关限制，最终输出可能因各通道限制而不同。停用主通道不会继续把强度复制到另一通道。波形切换互不跟随。

原版模式除最大强度设计外保留原始行为，包括 feel_scale、A 选择稳定窗口、B 动作推荐及覆盖、高潮/失败时序和原始 5 秒最大值 + 15 限制。新旧配置独立保存，切换不丢失另一模式的设置。

每个通道只有一个播放任务，强度的“归一化加权平均”不会叠加波形。强度按 `Σ(来源强度 × 权重) / Σ(所有配置来源的权重)` 计算；未激活或数据不可用的来源贡献为 0，但保留其分母权重，避免来源退出时放大其余来源。权重全部为 0 时输出为 0。配置仍使用原有 `weighted` 标识，不改写已保存的权重、强度范围和硬上限；事件强度与最终限幅仍使用原规则。

循环模式持续播放；单次模式从头播到尾，保持在同一规则时不重复，重新进入规则才重播。事件窗口、停止、暂停、缺少有效输入或更高优先级规则仍可提前中断单次播放；事件窗口应结合库中显示的波形时长设置，现有事件窗口上限为 5 秒。

## 完整波形与传输

导入支持 Dungeonlab `Dungeonlab+pulse:`、逐行 V3 HEX、2 列（频率码/振幅）或 8 列数字文本、参考项目的 `waveforms` JSON 集合、单波形 JSON 和兼容 16 点 JSON。JSON/HEX 的每个 100 ms 帧原样保存四组 25 ms 频率码/振幅，不压缩成 16 点。单文件最大 2 MiB，单波形最多 6000 帧；不合法集合整批拒绝，磁盘写入中途失败会撤回本批新建文件。

Dungeonlab 的频率索引是周期毫秒，按 V3 分段公式编码；不能直接把 Hz 当作协议频率码。`.pulse` 持续时间按 100 ms 帧量化，超过 V3 范围时明确报错，不静默裁剪。旧 16 点文件可以继续读取，编辑保存后成为完整帧格式。

发送队列采用每通道独立游标，约 300 ms 前瞻，按实际 100 ms 帧耗时补充。切换先清除该通道队列，再留出约 150 ms 间隔；B 不会被 A 的等待阻塞。周期切换同时检查实际已排队帧的位置，避免清除间隔使游戏计时与播放周期错位。单次完成后发送零强度。监视页显示已发送任务状态；强度显示已发送的协议值，不等于硬件测量。

旧波形选择、动作映射和来源波形可迁移为新版规则，同波形动作合并为名称列表；原始原版玩法仍独立保留。旧相位/混合入口不再参与运行时选择。旧“关闭波形”的来源保留零权重，防止迁移后意外增加输出。本轮验证使用临时配置，没有改写用户原配置；源码有修改前备份。第一次保存才将工作台策略写入配置。
