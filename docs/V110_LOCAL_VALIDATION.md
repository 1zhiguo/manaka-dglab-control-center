# v1.1.0 本地合并验收

本地审核分支基于累计改动 `9fa10d2`，合入上游 v1.1.0 `ca3c512`。此次保留为未提交的合并，不推送、不更新草稿 PR。

## 合并范围

- 解决构建脚本、遥测源码及 DLL、波形选择器、QML 主窗口、后端、翻译和启动入口共 8 个冲突文件。
- 保留原有 A/B 独立强度与检测绑定、0–200 上限、波形库标识和数据、事件规则、单次／循环播放、自适应预览、未保存草稿、统一控件及直接切换主题。
- 保留上游 V3/V4 选择、负鼠独立工作台与波形编辑、设备发现／连接状态、全局停止、游戏进程检测、HUD V2 与显示设置，以及其他自动合并的上游功能。
- 原版玩法可分别选择 A/B 的心率或动作来源，和其他玩法设置一起保存。已有上游来源配置可迁移；A/B 独立模式继续使用其独立绑定。来源改变后郊狼暂停，需手动启用，负鼠授权不受影响。
- 后台处理器支持 V4；切换协议时在处理锁内更换输出适配器并丢弃旧快照。保留 V4 的明确启用、归零确认、有限时长输出任务、超时停止及设备故障屏蔽。
- V4 执行各通道上限和设备反馈上限，支持长波形、单次播放与周期末切换。HUD V2 可显示 0–200，分别显示 A/B 上限。
- 保留原 A/B 监视页面，新增负鼠和设置页面；顶部仅有一个 HUD 开关。主题仍由按钮直接切换，没有动画设置或外观弹窗。

## 侧栏与 V4 端口修复

- 设置入口移入与其他标签相同的导航列表，使用相同间距与滚动行为；不再单独固定于状态卡片上方。中英文／浅深色各 22 个状态重新检查通过。
- 本机 Windows 排除端口范围包含 9993–10092，因此默认 V4 端口 9998 即使无人监听也可能绑定失败。没有更改系统端口保留、防火墙或服务。
- V4 优先使用 9998；遇到端口占用或访问被拒绝时，由系统分配可用端口。二维码、郊狼／负鼠共享路由、显示地址及现有网络修复按钮均使用实际端口。
- 清除失败或关闭后的旧二维码／服务状态；重新检测会重试现有 Hub，并通过 Hub 同步网卡地址，避免只修改单一路由。
- 回归覆盖真实端口占用、模拟 Windows 保留端口、备用端口也失败后的重试和界面错误恢复。打包连接诊断现在从默认 9998 启动，不再以端口 0 绕过默认端口问题。
- 使用此新构建后重新扫描当前二维码；实际手机、设备和游戏联动仍待用户本地验收。

## 本地人工测试

1. 解压整个测试包后启动程序；请保留 `_internal` 目录。
2. 检查已有玩法、通道上限、检测绑定和波形绑定是否正确；切换页面、修改检测绑定后，草稿应保持，保存后重新打开应一致。
3. 在设备与游戏页面分别检查 V3/V4 二维码和电脑地址。V4 发现设备后仍需手动启用；确认切换协议、暂停与全部停止的表现。
4. 关闭游戏，在现有 BepInEx 环境中更新本包 `plugins/ManakaDGLabTelemetry/ManakaDGLabTelemetry.dll` 后重启游戏，检查随机振动器档位、A/B 独立规则、负鼠联动及 HUD V2 内容／位置。将该目录复制至游戏的 `BepInEx/plugins` 即可；本次自动工作没有替换游戏目录中的插件。
5. 本机游戏和硬件实际播放效果由用户验收；模拟 App 测试不代表实机验证。

源码仍处于“冲突已解决、等待合并提交”状态。测试反馈确认前，不创建提交或推送。
