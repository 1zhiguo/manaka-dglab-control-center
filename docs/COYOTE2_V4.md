# 郊狼 2.0 / V4 适配与验证

本次适配发布为 v1.1.1，沿用已有游戏联动策略。v1.1.0 ZIP 不会自动获得此改动，请下载新版本。

## 连接与设备能力

- 郊狼 2.0（COYOTE_020）和 3.0（COYOTE_030）均可通过 DG-LAB 4 App / V4 Socket 接入。硬件代次与 Socket 版本相互独立，不新增蓝牙直连驱动。
- Pulse 角色只接受以上两种郊狼；负鼠角色只接受 OVC_1，独立选择、启停、队列与限幅。
- 自动发现/选择不代表输出授权。沿用 Manaka 现有 V4 手动启用流程；硬件就绪并完成归零后可在游戏启动前启用，等待新鲜游戏数据时保持零输出。
- APP Socket 已连接不代表设备蓝牙就绪；明确的 hasDevice=false 或 connectState=disconnected 会阻止输出。
- 2.0 不要求 3.0 专有的 channelAStatus / channelBStatus。3.0 原有电路故障检查保留。
- 每通道输出受策略目标、用户硬上限、APP 当前 intensityMax、协议范围 0～100 共同限制。缺失、未同步、布尔值、负数或非有限上限不允许非零输出；不使用最高可增长上限。

## 波形与停止确认

四采样 V3 帧仍为 8 字节（16 个十六进制字符），前四字节频率、后四字节幅度。V4 device.op 波形 data 显式使用 ver:3；不因硬件为 2.0 就改成 ver:2。

- 单帧：t:0、c:0/1、p:1、d:100、v:[frame]、im:true、ver:3。
- 持续强度：t:4、c:0/1、p:1、d:300、v:strength、im:true。
- 基线流程：A/B 的 t:7,v:0 完成确认 → device.op.clear 确认 → 再次 A/B t:7,v:0 完成确认。继续使用本项目请求 ID、响应与任务结束验证。
- 首次选择、设备/APP 重连均作废旧发送计划与旧会话，再建立基线；排队中的旧计划和旧启用命令不能跨会话恢复输出。
- 单通道屏蔽立即建立该通道归零屏障，另一通道继续独立工作；双通道屏蔽后重新建立整路基线。
- 用户主动暂停不被重连覆盖；解除急停不会自动重新启用。短租约、过期计划丢弃和发送独立事件循环保持。

## 游戏联动范围

保留 Manaka 的心率/动作 A/B 自由来源、官方预设、自定义波形、独立帧循环、动作渐强与负鼠固定/随机/动作/游戏振动器同步策略。本次不移植 SiNiSistar2 的游戏后端或 CG 播放列表。Manaka 的动作结束与不可操作场景停止按其原有策略验证。

## 验证入口

模拟 APP 仅连接 127.0.0.1，控制器测试监听 127.0.0.1 的随机端口；模拟 COYOTE_020 不提供 3.0 电路字段。测试使用独立临时配置，不读取真实设备或运行中的游戏。

源码运行：

```powershell
python tools/verify_coyote2_v4.py build/coyote2-validation/source.json
```

打包后使用相同场景：

```powershell
.\ManakaQmlControlCenter.exe "--validate-coyote2=C:\temp\manaka-coyote2-exe.json"
```

验证入口在正常窗口、单实例锁及真实服务初始化之前分流。报告包含每个场景的 RPC、相关任务完成响应及是否为 frozen EXE。

**验证边界：回环模拟通过不等于实体实测。尚未验证实体郊狼 2.0 的蓝牙输出或体感。** 测试不连接实体硬件。

最终测试数、报告与包校验值见本地 build/coyote2-validation 及 release 目录。
